版本：v1.0
作者 Claude Sonnet
适用引擎：QuickJS（通过 `flutter_qjs` 运行）

## 1. 插件是什么

一个数据源插件是**一个纯 JavaScript 文件**，负责两件事：

1. 告诉 App 应该**怎么发起网络请求**（URL、参数、签名等）
2. 告诉 App 应该**怎么解析响应**，把任意结构的 JSON 转换成 App 认识的统一文章格式

插件本身**不能直接访问网络、文件系统，也不能操作 DOM**。所有网络请求都由 App 在 Dart 层代理执行，插件只做纯数据计算，这是出于安全沙箱设计（详见第 6 节）。

一个最小可用插件长这样：

```js
// ==DataSourcePlugin==
// @id           hn_demo
// @name         Hacker News
// @version      1.0.0
// @author       yourname
// @description  Hacker News 热门文章聚合
// @icon         https://hn.algolia.com/favicon.ico
// @homepage     https://github.com/yourname/hn-plugin
// ==/DataSourcePlugin==

function buildRequest(ctx) {
  return {
    url: "https://hn.algolia.com/api/v1/search",
    method: "GET",
    headers: {},
    params: {
      tags: "story",
      page: ctx.page - 1,
      hitsPerPage: ctx.pageSize
    }
  };
}

function parseResponse(responseJson, ctx) {
  var hits = responseJson.data.hits || [];
  return hits.map(function (item) {
    return {
      id: item.objectID,
      title: item.title,
      thumb: item.thumbnail || "",
      summary: item.story_text || "",
      author: item.author || "",
      publishTime: item.created_at || "",
      detailUrl: item.url || ("https://news.ycombinator.com/item?id=" + item.objectID),
      contentHtml: null
    };
  });
}
```

## 2. 插件文件结构

插件是**单个 `.js` 文件**，由两部分组成：

| 部分 | 说明 |
|---|---|
| Manifest 注释头 | 文件开头的 `// ==DataSourcePlugin==` ... `// ==/DataSourcePlugin==` 块，声明插件元信息 |
| 脚本主体 | 必须导出 `buildRequest` 和 `parseResponse` 两个函数 |

---

## 3. Manifest 字段说明

```js
// ==DataSourcePlugin==
// @id           唯一标识，建议用小写字母+下划线，安装后不可重复
// @name         显示名称
// @version      语义化版本号，如 1.0.0
// @author       作者名
// @description  一句话描述数据源内容
// @icon         图标 URL（可选）
// @homepage     插件源码/说明地址（可选，用于用户了解插件详情）
// ==/DataSourcePlugin==
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `@id` | ✅ | App 内唯一标识，重复安装会提示覆盖更新 |
| `@name` | ✅ | 展示在数据源列表 |
| `@version` | ✅ | App 用于比对版本、提示插件更新 |
| `@author` | ❌ | |
| `@description` | ❌ | |
| `@icon` | ❌ | 建议提供，否则显示默认图标 |
| `@homepage` | ❌ | 便于用户查看插件来源是否可信 |

## 4. 必须实现的函数

### 4.1 `buildRequest(ctx)`

**作用**：返回本次请求的描述对象，由 App 在 Dart 层真正发起 HTTP 请求。

**入参 `ctx`（运行时上下文，App 自动传入）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `ctx.page` | number | 当前请求的页码，从 1 开始 |
| `ctx.pageSize` | number | 每页条数，由 App 设置传入 |
| `ctx.timestamp` | number | 当前毫秒时间戳，供签名算法使用 |
| `ctx.extra` | object | 用户在数据源设置中填写的自定义参数（如 API Key），见第 7 节 |

**返回值**（必须是一个对象）：

```js
{
  url: "https://api.example.com/list",   // 必填，请求地址（不含 query，query 用 params 单独传）
  method: "GET",                          // 必填，"GET" 或 "POST"
  headers: { "X-Token": "abc" },          // 选填，请求头
  params: { page: 1, sign: "xxx" },       // 选填，GET query 参数 / POST 表单参数
  body: null                              // 选填，POST JSON body（method 为 POST 且需要 JSON body 时使用）
}
```

**示例：带时间戳签名的请求**

```js
function buildRequest(ctx) {
  var timestamp = ctx.timestamp;
  var secret = "your_app_secret";
  var raw = "page=" + ctx.page + "&ts=" + timestamp + "&key=" + secret;
  var sign = CryptoJS.MD5(raw).toString();

  return {
    url: "https://api.example.com/v2/feed",
    method: "GET",
    headers: {},
    params: {
      page: ctx.page,
      pageSize: ctx.pageSize,
      timestamp: timestamp,
      sign: sign
    }
  };
}
```

### 4.2 `parseResponse(responseJson, ctx)`

**作用**：把原始响应 JSON 转换为统一格式的文章数组。

**入参**：

| 参数 | 说明 |
|---|---|
| `responseJson` | App 请求后拿到的响应体，已自动 JSON.parse，结构为 `{ data: <原始响应体> }` |
| `ctx` | 同 `buildRequest` 的 `ctx`，额外包含本次请求的 `ctx.page` |

**返回值**：必须是一个**数组**，数组每一项字段如下：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 文章唯一标识，用于去重/已读标记。若源数据没有天然 ID，可用标题+链接拼接后自行 hash |
| `title` | string | ✅ | 标题，为空的条目会被 App 自动过滤 |
| `thumb` | string | ❌ | 缩略图 URL，无图传空字符串 `""` |
| `summary` | string | ❌ | 摘要 |
| `author` | string | ❌ | 作者 |
| `publishTime` | string | ❌ | 发布时间，建议 ISO8601 格式或时间戳字符串 |
| `detailUrl` | string | 条件必填 | WebView 模式下必填，详情页跳转链接 |
| `contentHtml` | string \| null | 条件必填 | 原生渲染模式下必填，正文 HTML 或纯文本 |

> `detailUrl` 和 `contentHtml` 至少要有一个非空，取决于你希望详情页用 WebView 打开原文还是用 App 原生样式渲染正文。

**示例：字段名不规范、需要手动兜底的场景**

```js
function parseResponse(responseJson, ctx) {
  var list = responseJson.data.result && responseJson.data.result.items;
  if (!list) return [];

  return list.map(function (item) {
    var thumb = "";
    if (Array.isArray(item.images) && item.images.length > 0) {
      thumb = item.images[0].url;
    } else if (typeof item.cover === "string") {
      thumb = item.cover;
    }

    return {
      id: String(item.id || (item.title + item.pubDate)),
      title: item.title || "",
      thumb: thumb,
      summary: item.desc || "",
      author: item.source_name || "未知来源",
      publishTime: item.pubDate || "",
      detailUrl: item.link || "",
      contentHtml: null
    };
  }).filter(function (a) { return a.title.length > 0; });
}
```

## 5. 内置工具库

沙箱中预置了以下全局对象，**无需 `require` 或 `import`，直接使用**：

### 5.1 CryptoJS（签名/加密常用）

```js
CryptoJS.MD5(str).toString()
CryptoJS.SHA1(str).toString()
CryptoJS.SHA256(str).toString()
CryptoJS.HmacSHA256(str, key).toString()
CryptoJS.enc.Base64.stringify(CryptoJS.enc.Utf8.parse(str))   // Base64 编码
CryptoJS.enc.Base64.parse(base64Str).toString(CryptoJS.enc.Utf8)  // Base64 解码
```

### 5.2 console

```js
console.log("调试信息", someObject);
```

`console.log` 的输出会转发到 App 的插件调试日志面板（设置 → 数据源管理 → 插件详情 → 调试日志），方便排查解析问题。

### 5.3 encodeURIComponent / decodeURIComponent / JSON.stringify / JSON.parse

标准 JS 内置对象均可用，无需额外引入。

### 5.4 插件私有存储（可选）

若插件需要缓存少量状态（如临时 token），可用：

```js
pluginStorage.get("token");          // 读取，不存在返回 null
pluginStorage.set("token", "xxx");   // 写入
```

存储按插件 `@id` 隔离，不同插件之间不可互相读取，容量上限单插件 100KB。

## 6. 安全限制（请务必了解）

为保护用户设备安全，插件运行在**独立沙箱**中，以下能力被**禁止**：

- ❌ 不能发起任何网络请求（没有 `fetch` / `XMLHttpRequest`）
- ❌ 不能访问文件系统
- ❌ 不能访问其它插件的存储数据
- ❌ 不能执行超过 **5 秒**的同步计算（超时会被强制终止，`buildRequest`/`parseResponse` 各自独立计时）
- ❌ 不能加载外部脚本（`eval` 远程代码、动态 `import` 均不可用）

违反上述限制的插件调用会直接抛出异常，App 会提示"插件执行失败"并展示具体错误信息。

## 7. 用户自定义参数（`ctx.extra`）

有些数据源需要用户自己申请 API Key 才能使用（比如私有 API）。插件可以在 manifest 中声明需要哪些自定义参数，安装时 App 会自动生成表单让用户填写：

```js
// ==DataSourcePlugin==
// @id           my_api
// @name         My Private API
// @version      1.0.0
// @config       apiKey|API Key|text|必填，登录 xxx.com 获取
// @config       region|地区|select:cn,us,jp|默认 cn
// ==/DataSourcePlugin==
```

`@config` 格式：`字段名|显示名|类型|说明`，支持类型 `text`、`password`、`select:选项1,选项2`。

用户填写的值会注入到 `ctx.extra` 中：

```js
function buildRequest(ctx) {
  return {
    url: "https://api.example.com/feed",
    method: "GET",
    headers: {
      "Authorization": "Bearer " + ctx.extra.apiKey
    },
    params: { region: ctx.extra.region }
  };
}
```

## 8. 分页约定

- `ctx.page` 从 **1** 开始（不是 0）。
- 若目标 API 页码从 0 开始，请在 `buildRequest` 中自行 `ctx.page - 1` 转换（参考第 1 节示例）。
- App 判断"是否还有下一页"的规则：`parseResponse` 返回的数组长度 **小于** `ctx.pageSize` 时，视为已到最后一页，不再继续加载。若你的 API 返回的每页条数与请求的 `pageSize` 不一致，请确保这个约定仍然成立，否则会导致分页判断错误。

## 9. 开发与调试建议

1. **本地测试优先**：安装插件前，App 提供"测试连接"功能——填入插件 URL 后立即执行一次 `buildRequest` + 真实请求 + `parseResponse`，并展示解析出的前 3 条数据预览，确认无误后再正式启用。
2. **善用 `console.log`**：在 `parseResponse` 中打印中间变量，遇到解析失败时去 调试日志 面板查看具体报错和数据结构。
3. **字段兜底**：源 API 返回的字段可能为 `null`、`undefined` 或类型不一致（比如缩略图有时是字符串有时是数组），务必在插件中做好兼容判断，避免因为某一条脏数据导致整页解析失败。
4. **保持函数纯净**：`buildRequest` 和 `parseResponse` 应该是无副作用的纯函数（相同输入产生相同输出），不要依赖脚本顶层的可变全局变量保存状态——沙箱可能会在每次调用间重建。

## 10. 完整示例：需要签名的 API

```js
// ==DataSourcePlugin==
// @id           example_signed
// @name         示例签名数据源
// @version      1.0.0
// @author       demo
// @description  演示如何处理需要 HMAC 签名的 API
// @config       apiKey|API Key|text|在开发者后台申请
// ==/DataSourcePlugin==

function buildRequest(ctx) {
  var timestamp = ctx.timestamp;
  var nonce = String(timestamp) + Math.floor(Math.random() * 1000);
  var toSign = "page=" + ctx.page + "&pageSize=" + ctx.pageSize + "&ts=" + timestamp;
  var sign = CryptoJS.HmacSHA256(toSign, ctx.extra.apiKey).toString();

  return {
    url: "https://api.example.com/v1/articles",
    method: "GET",
    headers: {
      "X-Timestamp": String(timestamp),
      "X-Nonce": nonce,
      "X-Sign": sign
    },
    params: {
      page: ctx.page,
      pageSize: ctx.pageSize
    }
  };
}

function parseResponse(responseJson, ctx) {
  var body = responseJson.data;
  if (body.code !== 0) {
    console.log("接口返回错误", body.message);
    return [];
  }

  var list = body.data.articles || [];
  return list.map(function (item) {
    return {
      id: String(item.article_id),
      title: item.headline || "",
      thumb: item.cover_image || "",
      summary: item.brief || "",
      author: item.author_name || "",
      publishTime: item.publish_at || "",
      detailUrl: item.share_url || "",
      contentHtml: null
    };
  }).filter(function (a) { return a.title.length > 0; });
}
```

## 11. 发布与分发

- 插件本质是一个静态托管的 `.js` 文件，放在任意可公开访问的 URL（GitHub raw、自建服务器、CDN 均可）。
- 用户在 App 内「设置 → 数据源管理 → 添加插件」中输入该 URL 即可安装。
- App 会记录安装来源 URL，支持后续「检查更新」——重新拉取脚本并比对 `@version` 字段。
- 建议在 `@homepage` 中附上源码仓库地址，方便用户核实插件行为、提交 issue。

---

如有疑问或希望反馈内置工具库需求（如新增其它加密算法），请通过插件 `@homepage` 或 App 内反馈入口联系开发者。
